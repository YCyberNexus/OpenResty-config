# OpenResty 七层 WAF 离线部署与使用教程（CentOS x86_64）

适用环境：**CentOS 7/8 或 RHEL 8（el7/el8）x86_64 / 服务器无外网**。OpenResty 本体若**还没装**（`openresty -v` 报「没有那个文件或目录」），先看下方「前置：离线安装 OpenResty 本体」一节；已装好就直接从第 1 节开始。
本教程把项目部署目录统一定为 `/opt/openresty-waf/`（OpenResty 的 `-p` 前缀指向这里）。换别的路径时，把全文 `/opt/openresty-waf` 一起替换即可——**但不要放在 `/home` 下**（SELinux 默认禁止 nginx 读家目录，见第 13 节）。

> 这套只是方案里的 **P2（URL 黑白名单）+ P3（body 校验）**。它做的是「URL 准入 + 请求体合规校验」，**还没有**做客户端身份认证（mTLS 客户端证书是 P4）、也没有真正转发到上游——默认是个返回固定 JSON 的测试桩。怎么接真实上游 OpenClaw 见第 12 节。

---

## 前置：服务器还没装 OpenResty？先离线装本体（RHEL/el8 实战）

> 本节解决「`/usr/local/openresty/bin/openresty -v` 报『没有那个文件或目录』」——服务器上**根本还没装 OpenResty**。装好后回到第 1 节继续；已装好的跳过本节。

**为什么离线装 OpenResty 不麻烦**：官方 RPM 自带 nginx 和 LuaJIT，连 OpenSSL/PCRE/zlib 都打成**独立的 `openresty-*` RPM、放在同一个仓库目录**里，几乎不碰系统包。所以离线装本质上就是「抓 4 个 RPM、传过去、一条 `rpm -Uvh` 装齐」。

### 这 4 个包（RHEL 8 / el8 / x86_64）

| 文件 | 作用 |
|---|---|
| `openresty-<ver>-1.el8.x86_64.rpm` | 主包（nginx + LuaJIT） |
| `openresty-openssl3-<ver>-1.el8.x86_64.rpm` | 自带 OpenSSL 3（新版主包默认链这个） |
| `openresty-pcre2-<ver>-1.el8.x86_64.rpm` | 自带 PCRE2（正则） |
| `openresty-zlib-<ver>-1.el8.x86_64.rpm` | 自带 zlib（gzip） |

> 版本号会变。在 Mac 上 `curl -s https://openresty.org/package/rhel/8/x86_64/ | grep -oE 'openresty[^"]*\.rpm' | sort -u` 列目录挑最新一组。本文实测：`openresty-1.31.1.1` / `openssl3-3.5.7` / `pcre2-10.47` / `zlib-1.3.2`。

### 第一步：在 Mac 上下载

```bash
BASE="https://openresty.org/package/rhel/8/x86_64"
mkdir -p ~/openresty-el8 && cd ~/openresty-el8
curl -fSLO "$BASE/openresty-1.31.1.1-1.el8.x86_64.rpm"
curl -fSLO "$BASE/openresty-openssl3-3.5.7-1.el8.x86_64.rpm"
curl -fSLO "$BASE/openresty-pcre2-10.47-1.el8.x86_64.rpm"
curl -fSLO "$BASE/openresty-zlib-1.3.2-1.el8.x86_64.rpm"
curl -fSLO "https://openresty.org/package/pubkey.gpg"   # 验签用
```

### 第二步：打包传到服务器（通道同第 3 节：跳板机 / scp / U 盘）

```bash
cd ~ && tar -czf openresty-el8.tgz openresty-el8
shasum -a 256 openresty-el8.tgz        # macOS 上是 shasum,记下来核对
scp openresty-el8.tgz user@server:/tmp/
```

### 第三步：服务器上离线安装

```bash
cd /tmp && sha256sum openresty-el8.tgz   # 与 Mac 比对,确认没传坏
tar -xzf openresty-el8.tgz && cd openresty-el8
sudo rpm --import pubkey.gpg              # 不导入会有 NOKEY 告警,但不阻断安装
sudo rpm -Uvh openresty-*.rpm            # 4 个包同一条命令,rpm 自解依赖顺序
/usr/local/openresty/bin/openresty -v    # 出 nginx version: openresty/1.31.1.1 即成
```

> 也可 `sudo dnf install -y ./openresty-*.rpm`（对本地文件同样解依赖顺序），二选一。

### 换 CentOS 7 / 8 / RHEL 9 / ARM 怎么改

| 目标系统 | 仓库目录 | 包名后缀 |
|---|---|---|
| CentOS 7 | `centos/7/x86_64` | `.el7` |
| CentOS 8 | `centos/8/x86_64` | `.el8` |
| RHEL 8（本文） | `rhel/8/x86_64` | `.el8` |
| CentOS/RHEL 9 | `centos/9/x86_64`（仓库文件用 `openresty2.repo`） | `.el9` |
| ARM 服务器 | 把路径里 `x86_64` 换成 `aarch64` | 同上 |

> 想链老 OpenSSL 1.1.1 时把 `openresty-openssl3` 换成 `openresty-openssl111`；`rpm` 装时若提示缺哪个 openssl 变体，按它说的抓。

### 排障

| 现象 | 多半是 | 怎么修 |
|---|---|---|
| `rpm -Uvh` 报缺 `libstdc++`/`libgcc` 等系统库 | 基础系统库缺失（少见） | 从安装 ISO 的 `BaseOS`/`AppStream` 捞对应 RPM 一起 `rpm -Uvh`，不必联网 |
| `Header V4 RSA ... NOKEY` 告警 | 没导入 GPG 公钥 | `rpm --import pubkey.gpg`，或装时加 `--nogpgcheck`（仅告警，不阻断） |
| 装完仍报「没有那个文件或目录」 | 装到别的路径/装失败 | `rpm -ql openresty | grep bin/openresty` 看实际路径 |

## 0. 先理解部署后是什么

```
客户端 ──HTTP──> [本机:8080  OpenResty WAF]
                      │  access_by_lua: POST/PUT/PATCH 先做 Content-Type/JSON 预处理
                      │                 → 黑名单 → URL 白名单(未命中默认拒绝) → body schema 校验
                      │
                      ├─ 命中拦截 → 直接返回 4xx/5xx + {error, request_id}
                      └─ 放行 ────> content_by_lua 桩(当前) / proxy_pass 到 OpenClaw(生产, 第12节)
```

- 监听端口：`8080`（在 `conf/nginx.conf` 里，可改）。
- 规则文件：`conf/waf_rules.lua`（白名单 / 黑名单 / body schema，纯 Lua 表，改完热加载生效）。
- 运行期**零外部依赖**：`cjson.safe`、`ngx.re` 都是 OpenResty 自带，隔离网不需要 luarocks 联网装包。

---

## 1. 运行期到底需要哪些文件

打包脚本 `scripts/package.sh` 已经按这个清单帮你挑好，你不用手挑：

| 必须随包（运行期加载） | 说明 |
|---|---|
| `conf/nginx.conf` | 主配置，`-c conf/nginx.conf` 加载 |
| `conf/waf_rules.lua` | 规则表，`init_by_lua` 里 `require("waf_rules")` |
| `lua/waf/*.lua`（6 个） | handler / factory / decision / url_filter / body_validator / regex |
| `logs/`（**服务器上现建，不随包**） | `error_log`、`pid` 写这里；被 `.gitignore` 忽略，打包必漏，所以要手建 |

| 非请求运行必需（但可随包用于验证/参考） | 说明 |
|---|---|
| `spec/`、`Makefile` | 单元测试，只需 luajit，跟运行无关 |
| `docs/`、`README.md`、`*.docx` | 文档 |
| `schemas/chat_completions.schema.json` | P3-3 未来迁移目标，当前代码**没有** require 它（包里仍带着只是为了和文档一致） |
| `scripts/check_rules.lua`、`scripts/smoke.sh` | 规则体检与 curl 冒烟脚本，验收时手动跑（包里带着方便验证） |

## 2. 第一步：在开发机（Mac）上打包

在仓库根目录执行：

```bash
bash scripts/package.sh
# 产物：openresty-waf.tgz；末尾会打印 sha256，记下来传到服务器后核对
```

脚本做了三件隔离网容易忽略的事：①只挑运行期文件，解包后是干净的 `openresty-waf/` 顶层目录；②把 `*.sh/*.lua/*.conf` 的换行统一成 LF（防 CRLF 在 CentOS 上 `$'\r': command not found`）；③`COPYFILE_DISABLE=1` 打包，避免塞进 macOS 的 `._*` 垃圾文件。

> 推荐使用 `scripts/package.sh`。不想用脚本时，手打等价命令至少要包含规则体检脚本：
> ```bash
> COPYFILE_DISABLE=1 tar -czf openresty-waf.tgz \
>   conf lua schemas scripts/check_rules.lua scripts/smoke.sh scripts/server-setup.sh deploy
> ```

## 3. 第二步：把包传到服务器（离线）

无外网时按你现场可用的通道选一种，把 `openresty-waf.tgz` 弄到服务器：

- **跳板机 / 堡垒机文件传输**：多数内网有这个通道，直接上传。
- **scp/sftp（内网可达但无外网）**：`scp openresty-waf.tgz user@server:/tmp/`。
- **U 盘 / 光盘 / 单向导入闸**：物理介质拷贝。

传完**务必核对哈希**，确认没在传输中损坏：

```bash
# 服务器上
sha256sum /tmp/openresty-waf.tgz      # 与第一步 Mac 上打印的值比对
```

## 4. 第三步：解包到 /opt/openresty-waf

```bash
sudo mkdir -p /opt
sudo tar -xzf /tmp/openresty-waf.tgz -C /opt/
# 解包后即 /opt/openresty-waf/{conf,lua,schemas,scripts,deploy}
ls -l /opt/openresty-waf
```

## 5. 第四步：定位 openresty 二进制

官方 RPM 把真正的二进制装在 `/usr/local/openresty/bin/openresty`，并软链到 `/usr/bin/openresty`（可能在 PATH，也可能不在）。**生产一律用绝对路径**，避免和系统里其它 nginx 混淆：

```bash
# 优先用这个
/usr/local/openresty/bin/openresty -v
# 找不到就用包清单定位
rpm -ql openresty | grep -E 'bin/openresty|sbin/nginx'
```

下文命令统一写绝对路径 `/usr/local/openresty/bin/openresty`。

---

## 6. 第五步：准备运行环境（一条命令搞定）

包里带了 `scripts/server-setup.sh`，它会：定位二进制 → 建 `logs/` → 设好属主权限（整体 `root:nobody` 只读、`logs/` 给 `nobody` 可写）→ 跑一次 `openresty -t` 语法校验 → 最后打印 SELinux/firewalld 该执行的命令。

```bash
sudo bash /opt/openresty-waf/scripts/server-setup.sh
```

它**等价于**手动做下面这些（想自己来就照抄）：

```bash
sudo mkdir -p /opt/openresty-waf/logs
sudo chown -R root:nobody /opt/openresty-waf
sudo find /opt/openresty-waf -type d -exec chmod 750 {} +
sudo find /opt/openresty-waf -type f -exec chmod 640 {} +
sudo chown -R nobody:nobody /opt/openresty-waf/logs
sudo chmod 770 /opt/openresty-waf/logs
# 语法 + Lua 加载预检(强烈建议每次改完都先跑)
sudo /usr/local/openresty/bin/openresty -p /opt/openresty-waf/ -c conf/nginx.conf -t
```

为什么是 `root:nobody`：master 进程以 root 启动（好绑端口），worker 降权成 `nobody` 跑。Lua/配置给 `nobody` 组只读（防运行态被改），`logs/` 给 `nobody` 可写（不然 worker 写不了日志）。
> ⚠️ `logs/` 必须**先存在**，OpenResty 不会自动创建它，缺了直接 `[emerg] open() ".../logs/error.log" failed (2: No such file or directory)`。

## 7. 第六步：放行 SELinux 与 firewalld

先看状态：

```bash
getenforce                      # Enforcing 才需要下面 SELinux 步骤
sudo firewall-cmd --state       # running 才需要 firewalld 放行
```

**SELinux 为 Enforcing 时**（这是隔离网最常见、最坑的一类 502/Permission denied 来源）：

```bash
# ① 允许 nginx 绑定 8080(默认只放行 80/443 等)
sudo semanage port -a -t http_port_t -p tcp 8080 \
  || sudo semanage port -m -t http_port_t -p tcp 8080
# ② 让 nginx 能读 /opt 下的配置/lua(自定义目录默认上下文 nginx 读不了)
sudo semanage fcontext -a -t httpd_sys_content_t "/opt/openresty-waf(/.*)?"
sudo restorecon -Rv /opt/openresty-waf
```

> `semanage` 来自 `policycoreutils-python-utils`（CentOS 8）/ `policycoreutils-python`（CentOS 7）。隔离网若没装，先把这个 RPM 拷进来装上。排障工具也建议一起带齐：`audit`（出 `ausearch`）、`setools-console`。

**firewalld 开启、且要被其它主机访问时**：

```bash
sudo firewall-cmd --permanent --add-port=8080/tcp && sudo firewall-cmd --reload
sudo firewall-cmd --list-ports     # 确认有 8080/tcp
```

> 注意：本机 `curl 127.0.0.1:8080` 不过 firewalld，所以即使没放行，第 9 节的冒烟也会全绿——**联调时从对端机器才会暴露**。务必从别的机器实测一次。

## 8. 第七步：启动

### 方式 A：systemd（生产推荐，开机自启 + 崩溃自动拉起）

```bash
sudo cp /opt/openresty-waf/deploy/openresty-waf.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now openresty-waf
sudo systemctl status openresty-waf      # active (running) 即成功
```

常用：`systemctl reload openresty-waf`（改规则后热加载）、`systemctl stop/restart openresty-waf`、`journalctl -u openresty-waf -e`（看启动失败原因）。

### 方式 B：命令行（快速验证 / 临时起）

```bash
# 后台启动
sudo /usr/local/openresty/bin/openresty -p /opt/openresty-waf/ -c conf/nginx.conf
# 热加载 / 优雅停止(必须带和启动时完全一致的 -p 和 -c,否则找不到 pid)
sudo /usr/local/openresty/bin/openresty -p /opt/openresty-waf/ -c conf/nginx.conf -s reload
sudo /usr/local/openresty/bin/openresty -p /opt/openresty-waf/ -c conf/nginx.conf -s quit
```

> **关键**：`-p` 决定 `$prefix`，配置里 `logs/`、`lua_package_path "$prefix/lua/..."` 全相对它解析。漏掉 `-p` 或路径写错，会解析到 `/usr/local/openresty/nginx/` 去，表现为 `module 'waf.handler' not found`、日志写错地方。`-p` 值带结尾斜杠最稳（`/opt/openresty-waf/`）。

## 9. 第八步：验证（curl 冒烟）

```bash
which curl || echo "缺 curl,需离线装 curl + libcurl 的 RPM"
bash /opt/openresty-waf/scripts/smoke.sh
# 自定义地址: BASE=http://127.0.0.1:8080 bash .../smoke.sh
```

预期全部打勾，覆盖这 9 种情形：

| 用例 | 期望码 |
|---|---|
| 合法 chat 请求（放行） | 200 |
| 白名单内 `GET /v1/models` | 200 |
| 未在白名单的路径（默认拒绝） | 403 |
| 黑名单 `/v1/admin` | 403 |
| `model` 不在允许列表 | 422 |
| 出现未知字段（`additionalProperties`） | 400 |
| `system` 不在首位（防伪 system 注入） | 422 |
| 非 `application/json` 的 POST | 415 |
| 带 `x-openclaw-model` 覆盖头（防 model 旁路） | 403 |

没装 curl 时可用 OpenResty 自带的 `resty`，或 bash 的 `/dev/tcp` 手测：

```bash
exec 3<>/dev/tcp/127.0.0.1/8080; printf 'GET /v1/models HTTP/1.0\r\n\r\n' >&3; cat <&3
```

## 10. 怎么用：客户端该怎么发请求

WAF 把所有请求按 `conf/waf_rules.lua` 的规则判。当前规则（起步骨架，数值是占位，按接口契约再收紧）：

**白名单**（未命中一律 403）：
- `POST /v1/chat/completions` —— body 走 `chat` 校验器
- `GET /v1/models` —— 无 body 校验

**黑名单**（先于白名单，命中即 403）：`^/admin`、`^/v1/admin`（拦 OpenClaw 控制面/管理端点）。

**禁用请求头**（命中即 403，先于黑/白名单）：`x-openclaw-model`——OpenClaw 的“后端 model 覆盖头”，拦它防止客户端旁路下面的 model 白名单。

**`chat` body 校验规则**（按 OpenClaw OpenAI 兼容接口对齐；具体 agentId 与上限待部署确认）：
- `model` ∈ {`openclaw`, `openclaw/default`}（OpenClaw 形如 `openclaw/<agentId>`，按实例实际 agent 收紧）
- 只允许官方列明的字段：`model`、`messages`、`stream`、`user`、`temperature`、`top_p`、`frequency_penalty`、`presence_penalty`、`seed`、`max_tokens`、`max_completion_tokens`、`stop`（多一个未知字段就拒；`tools`/`tool_choice` 刻意未放开）
- `messages` 非空、条数 ≤ 50；每条 `role` ∈ {`system`,`user`,`assistant`}、`content` 为字符串
- **`system` 必须是第一条**（防伪造 system 越权）；单条 ≤ 8000、累计 ≤ 32000（按字节，中文偏大）

**放行示例**：

```bash
curl -X POST http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"openclaw","messages":[{"role":"user","content":"你好"}]}'
```

**返回码含义**（被拒只回 `{error, field?, request_id}`，不回显规则细节）：

| 码 | 含义 |
|---|---|
| 200 | 放行 |
| 403 | 命中黑名单 / 不在白名单 / 带禁用请求头（如 `x-openclaw-model`） |
| 415 | POST/PUT/PATCH 但 `Content-Type` 不是 `application/json` |
| 413 | body 过大落盘、无法在内存校验（fail-closed） |
| 400 | body 不是合法 JSON / body 结构不对（未知字段 / 缺 `model` 或 `messages` / `messages` 非数组或空 / `content` 非字符串等）/ 请求头过多被截断（`too_many_headers`，fail-closed） |
| 422 | body 策略不通过（model 不允许 / role 非法 / 条数或长度超限 / system 不在首位等） |
| 500 | 规则配置错误（白名单引用了不存在的校验器） |

## 11. 改规则与热加载

改 `conf/waf_rules.lua`（加白名单、调上限、加黑名单等），然后：

```bash
# 改完先体检 + 校验,通过再热加载,无中断
cd /opt/openresty-waf
/usr/local/openresty/luajit/bin/luajit scripts/check_rules.lua
sudo /usr/local/openresty/bin/openresty -p /opt/openresty-waf/ -c conf/nginx.conf -t
sudo systemctl reload openresty-waf          # 或命令行 -s reload
```

> 起步骨架是 Lua 表静态加载，靠 reload 生效。方案 P5 的「配置中心 + 版本号 + 加载前校验 + 回滚」还没接，先用规则体检和 `-t` 预检兜底，避免坏规则上线（`init_by_lua` 里规则错会让整个进程起不来，是 fail-closed）。

## 12. 接真实上游 OpenClaw（把测试桩换成转发）

当前 `conf/nginx.conf` 的 `location /` 里是 `content_by_lua` 桩，**放行的流量只回 `{"ok":true,"upstream":"stub"}`，不会真到 OpenClaw**。生产要改成 `proxy_pass` + 对上游 mTLS（方案 P4-1）。把 `http{}` 里那段改成：

```nginx
upstream openclaw_backend {
    server 10.0.0.10:443;     # 蓝区 OpenClaw 对外地址
    keepalive 16;
}

server {
    listen 8080;
    default_type application/json;

    location / {
        access_by_lua_block { require("waf.handler").access() }

        # 删掉原来的 content_by_lua_block,换成转发:
        proxy_pass https://openclaw_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Connection "";

        # 对上游做 mTLS 双向认证(证书放 /opt/openresty-waf/certs/,权限 640 root:nobody)
        proxy_ssl_protocols TLSv1.2 TLSv1.3;
        proxy_ssl_verify on;
        proxy_ssl_trusted_certificate /opt/openresty-waf/certs/ca.crt;
        proxy_ssl_certificate         /opt/openresty-waf/certs/client.crt;
        proxy_ssl_certificate_key     /opt/openresty-waf/certs/client.key;
        proxy_ssl_name openclaw.internal;     # 上游证书里的名字 / SNI
    }
}
```

改完别忘了两件 SELinux 相关的事：

```bash
# ① 允许 nginx 主动外联(否则 proxy_pass 报 502 + ausearch 里 name_connect denied)
sudo setsebool -P httpd_can_network_connect 1
# ② certs/ 也要让 nginx 能读
sudo restorecon -Rv /opt/openresty-waf/certs
```

## 13. 日志与排障速查

日志在 `/opt/openresty-waf/logs/error.log`（含每条请求的 `waf action=allow/deny ... reason=...`）。启动失败先看它，systemd 方式再加 `journalctl -u openresty-waf -e`。

| 现象 | 多半是 | 怎么修 |
|---|---|---|
| `command not found: openresty` | 二进制不在 PATH | 用绝对路径 `/usr/local/openresty/bin/openresty` |
| `[emerg] open() ".../logs/error.log" failed (2: No such file or directory)` | `logs/` 没建 | `mkdir -p .../logs` 并 chown（第 6 节） |
| `bind() to 0.0.0.0:8080 failed (13: Permission denied)`（root 启动也报） | **SELinux 没放行 8080**（不是 firewalld！） | `semanage port -a -t http_port_t -p tcp 8080`（第 7 节） |
| `module 'waf.handler' not found` / `'waf_rules' not found` | `-p` 没传或传错，`$prefix` 没锚到项目目录 | 带 `-p /opt/openresty-waf/`，先 `-t` 预检 |
| 文件明明在，却 `failed to load` / `read denied` | `/opt` 下 SELinux 上下文不对 | `restorecon -Rv /opt/openresty-waf`（第 7 节） |
| 本机 curl 通、别的机器连不上（超时） | firewalld 没放行 8080 | `firewall-cmd --add-port=8080/tcp --permanent && --reload` |
| `bind() ... (98: Address already in use)` | 8080 被占 / 旧实例残留 | `ss -ltnp | grep :8080` 查占用，停旧实例或清 `logs/nginx.pid` |
| `smoke.sh` 报 `$'\r': command not found` | 文件被存成 CRLF | `sed -i 's/\r$//' scripts/smoke.sh`（用 `package.sh` 打包可避免） |
| 换 `proxy_pass` 后 502 / 超时 | SELinux 禁 nginx 外联 | `setsebool -P httpd_can_network_connect 1`（第 12 节） |

> 快速判断是不是 SELinux 干的：`sudo setenforce 0` 临时切 permissive 再起一次，能起就是 SELinux 策略问题——**确认后务必 `setenforce 1` 切回**，按上面用 `semanage`/`restorecon` 正解，别长期关 SELinux。看具体拦截：`sudo ausearch -m AVC -ts recent`。
