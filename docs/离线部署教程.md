# 离线部署教程

当前版本按蓝/黄两个独立 WAF 节点部署，具体 URL 由运维活动规则决定。完整配置与验收见[双 WAF 白名单链路部署说明](双WAF白名单链路部署说明.md)。本页只描述离线交付步骤。

## 1. 开发机验证并打包

```bash
make lint
make test
bash scripts/package.sh /tmp/openresty-waf.tgz
shasum -a 256 /tmp/openresty-waf.tgz
```

`make lint` 检查仓库中的活动规则；若尚未由运维配置，它会提示空白名单并保持全部拒绝。打包前必须设置 `example=false`、正式版本/方向，并执行 `luajit scripts/check_rules.lua --production conf/waf_rules.lua`。

## 2. 通过批准的文件通道传输

通过堡垒机文件传输、受控 SFTP 或公司批准的介质/导入流程把包送到对应分区；不得新增绕过 ODCP/DLP/审计的临时通道。服务器上核对 SHA-256 后再解包：

```bash
sha256sum /tmp/openresty-waf.tgz
sudo mkdir -p /opt
sudo tar -xzf /tmp/openresty-waf.tgz -C /opt/
```

## 3. 渲染当前节点配置

蓝区：

```bash
cd /opt/openresty-waf
cp conf/nginx-blue.conf.template conf/nginx-blue.conf
# 安装已审批的 conf/waf_rules.lua，用已审批值替换占位符并安装 mTLS 材料
sudo NODE_ROLE=blue bash scripts/server-setup.sh
```

黄区把 `blue` 换为 `yellow`。脚本会创建 `/data/openresty-waf/<role>/audit`、检查残留占位符、运行规则体检、打印活动规则 SHA-256 并执行 `openresty -t`。两侧规则版本与 SHA-256 必须一致。材料不全时脚本会停止，不应通过注释校验或关闭 TLS 验证绕过。

## 4. 启动实例

```bash
sudo cp deploy/openresty-waf@.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now openresty-waf@blue   # 或 yellow
```

生产验收、SELinux、网络最小放行、审计查询和回滚要求见主部署说明。
